# Synology Drive Client 開發藍圖

## 1) 技術方向
- Desktop：Tauri 2（Windows 優先）
- Sync Engine：Rust
- UI：React + TypeScript
- NAS 通訊：DSM Web API（`SYNO.API.Auth`、`SYNO.SynologyDrive.Files` / `TeamFolders`），不使用 WebDAV

## 2) 產品範圍

### 範圍內
- 真實 DSM 帳密登入（含 OTP 兩步驟驗證），登出時銷毀 session
- 多個同步資料夾，各自設定模式：雙向 / 僅上傳（本機 → NAS）/ 僅下載（NAS → 本機）
- 本機監看（notify）+ 定期檢查 NAS，自動同步；也可手動「立即同步」
- 衝突不盲目覆蓋：兩邊都改時保留兩份，並記錄在衝突管理
- 「刪除也同步」（每個資料夾的選項，預設關閉）：移到資源回收桶，不永久刪除
- 區網直連：在家裡的區網改走 NAS 的區網位址（可限定 Wi-Fi），避開 Cloudflare 的 100 MB 單檔上限
- 檔案總管同步狀態圖示（綠色勾 / 同步中箭頭）
- 同步佇列、進度、App 內 toast 與 Windows 系統通知
- 系統匣常駐、關窗縮到系統匣、單一實例

### 不在範圍內（已決定不做）
- **Files On-Demand**（placeholder / 按需下載 / 釋放空間 / 釘選）：檔案一律完整存在本機；只做狀態圖示
- **OIDC / SSO 登入**：token 交換未實作，登入頁已停用；僅保留帳密 + OTP
- **分塊上傳**：Drive 網頁 API 沒有分塊機制（上傳是單一請求），改以區網直連解決大檔
- **WebDAV / 多 Provider 抽象**（`RemoteProvider`、`FakeRemote`）：已確定直接使用 Drive API
- **平行傳輸與頻寬限制**、**NAS 端修改時間比對**（目前只比大小）
- **檔案總管左側導覽入口**（需套件身分，成本高）
- 把同步內容送第三方 AI

## 3) 安全基線
- NAS 一般位址全程 HTTPS，預設驗證憑證，不提供全域略過 TLS 驗證
- 區網位址只接受私有網路位址（192.168.x.x、10.x.x.x、172.16-31.x.x、`.local`），可用 http；登入仍走一般位址
- 帳密與 session 只在後端，不回傳前端；IPC 最小權限、CSP、移除 opener
- 外部輸入（檔名、遠端回應）一律視為資料；檔名依 Windows 規則清理，不能跳出同步根目錄
- 破壞性操作（刪除、覆蓋）需條件檢查：NAS 端覆蓋前保留歷史版本；刪除一律移到資源回收桶；一次大量刪除會中止

## 4) 同步規則

### 流程
列出 NAS 與本機 → 與「上次同步紀錄」比對產生計畫（純函式）→ 逐項上傳 / 下載 / 建立資料夾 / 刪除。上次同步紀錄每個資料夾一份（`sync-state/<folderId>.json`），記錄本機大小與修改時間、NAS 大小，以及已同步的資料夾。

### 觸發
- 登入後自動啟動同步服務與本機監看；新增 / 繼續資料夾時立即同步一次
- 本機有變動：距離上次同步結束 ≥30 秒後上傳
- 定期檢查 NAS：預設每 5 分鐘（可設定 1 分鐘 ~ 每天）；可關閉自動同步，只手動同步
- 上次失敗 / 出錯 / 取消：等下一次定期檢查才重試，避免連鎖重試

### 決策
- 只有本機改了 → 上傳為新版本（NAS 保留舊版）；只有 NAS 改了 → 下載取代
- 兩邊都改了 → 保留兩份（本機改名為「檔名 (衝突副本 時間).副檔名」並寫入衝突管理，再下載 NAS 版）；僅上傳模式以本機為準
- 第一次同步兩邊同名但大小不同 → 視為兩邊都改
- 缺檔一律補回：本機缺的從 NAS 下載、NAS 缺的重新上傳（依模式）；不會因為「之前同步過」就不補
- 開啟「刪除也同步」（僅雙向 / 僅上傳）：同步過的檔案只有一邊被刪除且另一邊沒改過，另一邊才移到資源回收桶；沒有同步紀錄的檔案絕不刪；僅上傳只刪 NAS；資料夾底下還有要保留的項目時不刪資料夾；單次刪除超過已同步檔案一半（且 ≥10 個）中止
- 名稱衝突（一邊是檔案、一邊是資料夾）→ 標為失敗，不處理
- 忽略：暫存檔（`.synodl-part`）、`~$` 鎖定檔、desktop.ini、Thumbs.db、.DS_Store、符號連結
- 下載先寫暫存檔，確認大小後才改名；上傳前確認檔案沒被修改；連續 5 個檔案失敗即停止；session 過期立即中止

### 連線路徑
- 登入與預設路徑：設定的 NAS 位址（可能經 Cloudflare 等代理）
- 區網直連：每次同步開始偵測 Wi-Fi 與區網位址可連線性，連得到則改走區網；用區網列出失敗就退回一般位址
- 經代理上傳超過約 100 MB 會被拒絕（HTTP 413）：顯示明確說明、記住該大小以上的檔案不再重傳，且不計入連續失敗
